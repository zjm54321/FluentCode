    - **严格范围界定**：仅针对标签头部的 busy 动画，绝不触碰消息流滚动位置，绝不伪造虚假任务百分比；成功/失败/等待提问状态由官方底层真实事件驱动。
    - **自适应与性能休眠**：不同标签宽度按相对归一化比例映射；支持系统减弱动画设置；当无任何 working 标签或视图卸载时，自动休眠/注销动画时钟，严禁引入任何多余后端网络轮询。
  - **已恢复瞬态错误投影消除与工具错误全行红色语义（Task B14 事实依据）**：
    - **基于实际续接/恢复关系智能消除（非僵硬 responseID 匹配）**：针对可恢复传输/API/服务端中断重试错误（如 upstream breakdown, response interrupted 等瞬态错误），界面仅显示当前处于未恢复状态者。根据用户明确要求，“下一次后面成功继续了”也需清除旧报错，因此成功续接可能是同会话中后续发起的新的 request/attempt 或新一轮流式推进，**不应僵硬要求 responseID 完全相同**；系统依据实际的续接与因果恢复关系，在会话后续成功推进后，自动隐藏先前相关的已恢复错误，不再残留已过时的失败说明。
    - **防误清与数据真实性红线**：严禁利用另一会话或当前会话中无关事件将真正未恢复的错误全部掩盖；严禁仅凭“重试中（Retrying）”状态就误判为已恢复；**仅在前端展示层隐藏已恢复的 API/transport/interrupted 错误，绝对不删除服务端诊断与历史数据，绝对不擅自将真实仍然失败的工具结果判定为已恢复**。
    - **未恢复工具错误全行红色语义**：未恢复的工具调用失败与全局错误视觉规范对齐，整个工具错误行/卡片采用红色语义表达（文字、图标、边框或背景按可读性渲染），彻底废除仅在最右侧显示单薄红叉的旧样式；严格保持主题与无障碍对比度。

## 9. 附录：阶段 A 关键技术架构与并发防冲撞细则 (Oracle 规范)

### 9.1 会话代际与防串防护机制 (Task A3)
- **复合寻址键**：所有会话状态定位必须基于 `source + directory + sessionID` 复合唯一键。
- **代际版本与所有权校验**：在发起异步消息获取时生成唯一的 `RequestOwnerToken` 并携带当前的 `pageGeneration` 与 `sourceRevision`；当异步结果或其 `finally` 回调触发执行时，首先比对当前视图的代际标记是否依然匹配。若已发生会话切换，则立即静默丢弃旧响应，且**绝对拦截旧 finally 块对加载状态或错误标识的复位操作**，杜绝闪烁与串会话状态污染。

### 9.2 草稿分槽与令牌校验架构 (Task A7)
- **双轨槽位隔离模型**：
  - `BlankSessionSlot`：通过 `DraftGUID` 独立索引，每个新建未命名的空白标签页各自独占一个槽位，初始配置读取系统默认，互不继承。
  - `PersistentSessionSlot`：通过 `source + directory + sessionID` 复合键严格分槽。
  - **身份稳定性**：草稿槽位身份（Draft Identity）稳定持久，不随 Tab 切换引起的渲染代际变化而发生漂移。
- **安全切换执行序列**：
  ```
  SwitchTab(targetSlot):
    1. CaptureAndSave(currentSlot.DraftState, currentEditToken)
    2. AbortPendingOperations(currentSlot)
    3. UpdateActiveSlot(targetSlot)
    4. IssueNewEditToken(targetSlot)
    5. RestoreDraftState(targetSlot)
  ```
- **关键操作令牌校验**：在模型选择器切换（picker）、新会话创建（create）以及消息发送（send）时，必须校验 `activeSlot == contextSlot && activeEditToken == currentEditToken`，防止异步迟到操作写入错误槽位。

### 9.3 视口渲染水位与已读确认机制 (Task A5)
- **状态正交性**：未读小圆点（Badge dot）与任务执行结果（Success / Failure / QuestionBlocked）完全正交，独立计算展示。
- **渲染水位感知**：已读回执的触发时机严格禁止“点击 Tab 即刻清除”，必须绑定到会话消息在可视视口内完成真实排版与绘制（Viewport Render Watermark）。当且仅当目标会话的新增消息被真实渲染展示给用户后，才触发确认消除小圆点，杜绝用户点击后瞬退导致漏看通知。

### 9.4 Recent 记录与写入容错机制 (Task A2)
- **精准捕获时机**：严格仅在发送管道最终收到服务端真实成功回执时，按照捕获的 `provider / model / source` 三元组记录；会话创建（create）或切换接管（handoff）时绝不记录。
- **Key 规范化与 MRU 淘汰**：存储键由 `{source}:{providerID}:{modelID}` 稳定复合构成，明确剔除 variant 变体参数；按最近真实使用排序与淘汰，采用 MRU（Most Recently Used）有限容量历史管理。
- **原子无损容错**：采用原子写入并替换的持久化策略；若捕获到 IO 或序列化持久化失败，必须静默记录告警日志，**严禁将异常向上抛出中断管道，绝对不得导致消息重新发送**。
- **概念规范说明**：文档中提及的 `RequestOwnerToken`、`SendSuccessReceipt`、`DraftGUID` 等属于架构概念规范，实施时复用现有数据绑定、代际标记与网络成功回执机制，不要求在代码中专门创建同名类或接口。
