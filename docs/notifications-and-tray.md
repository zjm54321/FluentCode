# 系统通知、任务栏与托盘集成

本文档介绍 FluentCode 与 Windows 系统的集成机制，包括原生 Toast 弹窗通知、交互式权限审批、Win32 任务栏状态投影以及系统托盘后台模式。

---

## 1. 原生 Toast 通知服务（`CompletionNotificationService`）

FluentCode 通过 Windows App SDK 的 `AppNotificationManager` 注册并发布原生系统通知，无需打包为 MSIX 即可正常工作。

### 1.1 注册与生命周期
- **通知源标识**：应用启动时以标识名 `FluentCode` 及应用图标（`Assets/AppIcon/app-48.png`）进行登记。
- **UI 线程隔离**：通知事件订阅在主 UI 线程进行，处理函数在主调度器上流转。应用退出时，自动注销通知监听并释放所有内存映射。

### 1.2 任务完成通知（Completion Notification）
- **触发判定**：仅当会话从活跃状态转为稳定的 `idle` 终态，且服务端返回的 `outcome == "succeeded"` 时，才会触发完成通知。
- **前台静默抑制**：若当前会话正处于主窗口前台可见激活状态，系统自动抑制通知弹出，避免重复打扰。
- **安全不透明令牌（Opaque Token）**：
  - Windows Toast 的启动参数**绝不包含**服务地址、会话 ID、凭据或对话内容。
  - 每次成功提交通知时，服务端在内存中生成一个专属的 32 字节随机 Token，并在内存注册表中建立与会话的关联（容量上限 256 项，有效期 10 分钟）。
  - 用户点击系统通知时，应用根据该 Token 解析对应会话并激活窗口；若 Token 已过期或进程已重启，应用安全降级为仅激活主窗口，绝不进行臆测导航。

## 2. 交互式通知与表单审批

对于模型发起的敏感权限（Permission）与表单提问（Form），FluentCode 支持在 Windows 通知横幅中直接提供交互按钮与文本框。

```
┌─────────────────────────────────────────────────────────────┐
│ 🔔 FluentCode                                               │
│ 智能体请求执行文件修改操作                                    │
│ 涉及文件：src/FluentCode/MainWindow.xaml.cs                 │
├─────────────────────────────────────────────────────────────┤
│   [ 单次允许 ]         [ 始终允许 ]         [ 拒绝 ]        │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 随机 Nonce 与安全映射
- 通知上的每一个动作按钮（Once / Always / Reject）与输入字段均绑定一个独立的运行期随机 Nonce。
- 用户在通知横幅中点击或输入时，系统通过该 Nonce 关联到内存中的待处理任务，绝不信任操作系统回传的未经验证的外部参数。

### 2.2 状态仲裁协同（`OpenCodeInteractionGate`）
- 在向服务端发送审批之前，通知回调函数首先获取对应会话的 Gate 租约（Lease），向服务端重新拉取最新状态并比对请求指纹。
- 若指纹一致，提交审批；若服务端已取消或指纹发生变更，通知操作作废并引导用户回到主界面重新查看。
- 无论何种异常断网，均标记为 `OutcomeUnknown`，绝不在后台静默自动重试。

### 2.3 原生输入边界与降级
若模型提出的问题类型超出了 Windows 原生通知输入框的表达能力（例如多选列表或格式受限的选择器），通知服务自动降级为“仅导航通知”。通知横幅仅作提示，引导用户点击后在应用主界面的提问卡片中完成完整交互。

## 3. Windows 任务栏状态投影（Taskbar Projection）

FluentCode 通过 Win32 原生 COM 接口 `ITaskbarList3`，在任务栏图标上映射当前工作状态。

### 3.1 状态映射规范
每次状态变更由 `TaskbarStatusService` 进行原子快照替换：

| 聚合状态 | 任务栏进度条（Progress） | 任务栏角标（Overlay Icon） | 屏幕助读文本 |
|---|---|---|---|
| **Idle**（空闲） | `TBPF_NOPROGRESS`（清除进度） | 无角标（清除） | — |
| **Working**（运行中） | 无测量总量时发 `TBPF_INDETERMINATE`；有明确度量时发 `TBPF_NORMAL` | 无角标 | “FluentCode：正在执行” |
| **NeedsAttention**（需处理） | `TBPF_NOPROGRESS` | 黄色警示三角角标 | “FluentCode：有任务需要处理” |
| **Completed**（完成） | `TBPF_NOPROGRESS` | 绿色对勾角标 | “FluentCode：任务已完成” |
| **Failed**（失败） | `TBPF_ERROR`（红色警示条） | 红色叉号角标 | “FluentCode：任务失败” |

### 3.2 优先级仲裁逻辑
当应用内有多个会话并行运行时，任务栏遵循严密的优先级策略：
```
NeedsAttention（等待用户审批/输入） > Working（正在执行中） > Failed（未确认的失败） > Completed（未确认的完成） > Idle（空闲）
```

### 3.3 TB1 状态角标与主题自适应
Windows 任务栏图标角标由系统统一绘制在图标右下角，其底色跟随 Windows 系统主题（深色约为 `#202020`，浅色约为 `#F3F3F3`）。
- FluentCode 采用自主设计的 **TB1 圆形状态角标**（包含 16、20、24、32 px 多分辨率帧），并在深浅色两套主题下光学优化，满足 WCAG 相对对比度标准（≥ 4.7:1）。
- 当系统深浅色偏好切换时，`TaskbarWindowHook` 自动重新加载匹配当前主题的私有 `HICON` 并重新提交。

### 3.4 Explorer 进程重启自愈
当 Windows Explorer 意外崩溃或重启时，所有已注册的 `ITaskbarList3` 状态均会丢失。`TaskbarWindowHook` 注册了系统级 `TaskbarButtonCreated` 广播消息，一旦收到系统重建通知，自动重置 COM 接口并重放最新的状态快照。

## 4. 系统托盘与后台常驻模式

用户可在设置中启用“关闭窗口时最小化至系统托盘”：
- **无感驻留**：点击窗口标题栏的关闭按钮时，主窗口隐藏，系统托盘区域常驻 FluentCode 图标。
- **后台持续监听**：后台线程继续维护与 OpenCode 的 SSE 实时长连接，任务完成或出现权限提示时依旧正常弹出 Windows Toast 通知。
- **托盘菜单**：
  - 双击托盘图标：唤起并激活主工作窗口。
  - 右键托盘菜单：提供“显示主窗口”与“退出应用”。点击“退出”将彻底断开连接、释放所有 PTY 终端并干净退出进程。
