# Critical test suite

On 2026-10-30 the suite was pruned to 25 critical entries (26 since 2026-10-31, when `fluent-motion/run.ps1` was added for the motion tokens and reduce-motion policy): `opencode-auth/run.ps1`, `opencode-connection/run.ps1`, `opencode-pairing/run.ps1`, `opencode-event-sync/run.ps1`, `message-pagination/run.ps1`, `opencode-view-ack/run.ps1`, `opencode-observations/run.ps1`, `notification-form/run.ps1`, `opencode-composer/run.ps1`, `opencode-composer-hookup/run.ps1` (default only, no `-NativeOnly`), `opencode-commands-attachments/run.ps1`, `opencode-queued-withdraw/run.ps1`, `opencode-plugin-mutations/run.ps1`, `opencode-session-controls/run.ps1`, `opencode-session-ui-state/run.ps1`, `fluent-motion/run.ps1`, `opencode-session-return/run.ps1`, `opencode-capabilities/run.ps1`, `opencode-browser-engine/run.ps1`, `browser-runtime/run.ps1`, `opencode-browser-settings/run.ps1`, `desktop-bridge-qol/run.ps1`, `opencode-persistent-pty/run.ps1`, `opencode-persistent-pty-transport/run-backend.ps1`, `browser-runtime/runtime.test.mjs`, and `browser-runtime/audit.test.mjs` (all paths relative to `tests/`).

From WSL at the repository root, plan with `python3 tests/run-suite.py --root "artifacts/fluentcode-step1-suite-$(date -u +%Y%m%dT%H%M%SZ)"`; add `--execute` to run sequentially. The root must be new. Each runner gets isolated logs/temp and, where supported, `-EvidenceRoot`; the driver stops if tracked or nonignored untracked candidate files change. The two Node tests use the bundled `artifacts/browser-runtime/node.exe`. Windows PowerShell 7, Visual Studio MSBuild, .NET 10, the prepared browser runtime and the retained runners' cached dependencies are required.

Since the 2026-10-31 launch regression, there are **27 entries**, including `startup-smoke/run.ps1`. This runner builds and publishes the main application in **Release**, launches it for at least 15 seconds, and verifies a live HWND owned by that exact PID plus a UI-dispatcher readiness marker. It navigates to OpenCode and exercises motion reset/entrance/reposition followed by XAML Scale APIs on a loaded element, catching handout-Visual/facade conflicts that headless tests cannot detect. `FC_STARTUP_SMOKE_ROOT` opts only the launched test process into a unique instance key, disposable settings/secrets/sessions and WebView profile (`about:blank`); toast/tray/taskbar registration and backend ownership are skipped. Existing user instances remain untouched. Unhandled XAML errors fail the test even if the app marks them handled. Cleanup posts close only to the test process and forcibly stops only that PID if necessary. To test an existing publish, pass `-PublishDirectory <absolute publish path> -EvidenceRoot <new directory>`; evidence includes results, any failure text, readiness marker and executable/DLL/PRI hashes.

The standalone desktop regression `theme-refresh/run.ps1 -PublishDirectory <native app output> -EvidenceRoot <new directory>` checks same-process app/System theme changes, rendered logo/provider pixels, agent/editor colors and checked native icon foregrounds. It temporarily changes Windows' app theme and restores it in `finally`, so it is deliberately outside the unattended suite. See [runtime theme refresh](theme-refresh.md) for the fixed-site audit, invocation and screenshot evidence.

The suite contains **27 entries**. FluentCode uses its own fresh profile without importing prior application data. Local/Web chat, provider/model and cookie-cleaning implementations have been removed; no retained runner depends on them.

Historical runner paths and results elsewhere in the documentation describe earlier evidence, not additional current suite entries. The inert conversation-view host now lives in `tests/opencode-session-return/ConversationView.TestHost.cs`; the persistent-PTY dependency build helper now lives in `tests/opencode-persistent-pty/BuildNativeTerminal.ps1` and is not a separate suite entry.
